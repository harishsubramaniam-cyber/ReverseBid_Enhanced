Uploading ReverseBid to GitHub

A backup, a way to hand the code to a developer, and a record of every change you ever make. Twenty minutes, most of it installing one app.

  • Windows
  • ~20 minutes
  • Free account
The hard part is already done

The folder you unzipped is already a Git repository, with the whole project committed to it in two labelled saves. You are not starting from scratch — you are pointing it at GitHub and pressing send.

First: the one thing that matters

Two things in that folder must never reach GitHub:

  • .env — if you have set up email, this holds your mail password.
  • data\ — the database, which will hold real supplier names and prices.

This is already handled: a file called .gitignore lists both, and Git obeys it without being asked. You need do nothing — but there is a checking step further down, and it is worth doing. Anything pushed to GitHub stays in its history even after you delete it.

Two routes to the same place

Take this one

Route A · GitHub Desktop

An app with buttons. Install, point it at the folder, click Publish. No typing.

If you prefer

Route B · The command line

The same thing typed out in four lines. Useful if the app misbehaves.

Route A — GitHub Desktop

1

Install it

Download from desktop.github.com and install it. Open it and sign in with your GitHub account when it asks.

2

Point it at the folder

  1. Menu File → Add local repository…
  2. Click Choose… and select C:\ReverseBid — the folder with README.md directly inside it.
  3. Click Add repository.

In the middle of the window it will say “No local changes”. That is correct: it means everything is already committed and ready to go up.

If it refuses

“This directory does not appear to be a Git repository” means you picked the wrong folder. The right one has README.md sitting directly inside it.

3

Publish it

  1. Click the Publish repository button at the top.
  2. Name: reversebid, or anything you like without spaces.
  3. Keep this code private — leave this ticked unless you deliberately want the world to read it. You can change your mind later.
  4. Click Publish repository.

It uploads in a few seconds. Then Repository → View on GitHub opens it in your browser.

Route B — the command line

1

Install Git

Download Git for Windows from git-scm.com/download/win. Every default option is fine — keep clicking Next.

2

Tell Git who you are

Once, ever. Press the Windows key, type cmd, press Enter, and run these with your own details:

Command Prompt
git config --global user.name "Harish Subramaniam"
git config --global user.email "harish.subramaniam@iiml.org"
3

Make an empty repository on GitHub

  1. Go to github.com/new.
  2. Repository name: reversebid.
  3. Choose Private, unless you want it visible to everyone.
  4. Leave every box below unticked and both dropdowns on None.
  5. Click Create repository, then copy the web address it shows you.
Do not add a README

If you tick “Add a README file”, or pick a .gitignore or a licence, the repository will not be empty and your upload will be rejected. It has to start with nothing in it.

4

Send the code up

Back in Command Prompt. Replace the address on the second line with the one you just copied:

Command Prompt
cd /d C:\ReverseBid
git remote add origin https://github.com/yourname/reversebid.git
git branch -M main
git push -u origin main

A browser window pops up asking you to sign in to GitHub. Do that, and the upload finishes by itself. You only sign in the first time.

Check it worked

Open your repository page on github.com and tick these off:

If one of the last two is there

Tell me and I will help you strip it out properly — and if a mail password was inside it, change that password today. Deleting the file on its own is not enough, because Git keeps the history.

You may also see a small orange dot or a green tick beside the newest commit. That is GitHub running the project's own test suite on its machines. Click it to watch. A green tick means all seventy-odd checks passed — bidding rules, emails, reports, the lot. It is already set up.

Making changes later

Every change you save is a labelled point you can go back to.

With GitHub Desktop

  1. Change whatever you want in the files.
  2. Open GitHub Desktop — your changes are listed down the left.
  3. Type a short note in the Summary box, bottom left: “Reworded the minimum decrement hint”.
  4. Click Commit to main, then Push origin at the top.

On the command line

Command Prompt
cd /d C:\ReverseBid
git add -A
git commit -m "Reworded the minimum decrement hint"
git push

Private or public?

  • Private — only you and the people you invite can see it. Right for anything carrying your organisation's process or plans. Free, with no limit on how many.
  • Public — anyone can read it. Safe for this code, which holds no passwords, but the README does describe how you run auctions.

Switch at any time: repository → Settings → bottom of the page → Change repository visibility. To let a colleague or a developer into a private repository: Settings → Collaborators → Add people.

If something goes wrong

What you seeWhat it means, and what to do
remote origin already exists You have run the git remote add line before. Use git remote set-url origin <address> instead.
Updates were rejected because the remote contains work that you do not have The GitHub repository was not empty — usually a README got added when you created it. Simplest fix: delete that repository (Settings → bottom → Delete this repository) and make a new one with nothing ticked.
src refspec main does not match any The branch is called something else. Run git branch -M main first, then push again.
'git' is not recognized Git is not installed, or your Command Prompt window was already open when you installed it. Close the window, open a new one, try again.
GitHub Desktop: “does not appear to be a Git repository” Wrong folder. Choose C:\ReverseBid — the one containing README.md.
It asks for a password and then refuses it GitHub stopped accepting account passwords for this. Sign in through the browser window it opens instead; if no window appears, use Route A.

What actually got uploaded

  • app\The application itself — the auction engine, the emails, the screens.
  • docs\These two guides.
  • tests\The automated check that walks a whole auction end to end.
  • seed.pyBuilds the demo suppliers and auctions.
  • README.mdThe technical description. GitHub shows it on the front page.
  • DockerfileFor putting it on a server later, when you outgrow your own PC.
  • .env.exampleA blank template listing the settings that exist. Your filled-in .env stays on your PC.
